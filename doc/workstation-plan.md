# Seiko Work 工作站实施计划

> 目标：做一个面向个人的工作站，能接收邮件、安排每日工作，并记录工资、请假、五险一金、日程。
> 核心原则：**优先最小完成度**，先跑通个人日常使用的主路径，再逐步扩展。

---

## 1. 技术栈（沿用现有）

| 层级 | 技术 |
|------|------|
| 后端 | Spring Boot 3.4 + Java 21 + MyBatis-Plus + MySQL 8 + Redis |
| 认证 | Sa-Token（已存在） |
| 邮件 | Spring Boot Starter Mail / Jakarta Mail（IMAP） |
| 前端 | Next.js 15 + React 19 + TypeScript + Tailwind CSS 4 + axios |
| 文档 | Knife4j / SpringDoc OpenAPI（已存在） |

---

## 2. 第一期 MVP 范围

### 2.1 邮件中心
- 用户需要维护多个 IMAP 邮箱账号（应用授权码/密码）。
- 定时任务每 5 分钟拉取一次未读邮件，存入本地数据库。
- 前端展示邮件列表（发件人、主题、时间、是否已读）。
- 支持查看邮件正文（纯文本优先，HTML 做安全过滤后展示）。
- 支持手动“从该邮件创建任务”，预填标题和正文摘要。

> 最小完成度说明：本期不解析邮件自动创建任务；由用户确认后生成工作事项。

### 2.2 工作事项 / 每日安排
- 从邮件或空白创建任务。
- 任务字段：标题、内容、计划日期、状态（待办/进行中/完成）、优先级、关联邮件。
- 首页“今日工作”视图：按日期展示当天及逾期的任务。
- 支持拖拽/选择日期调整计划。

### 2.3 工资记录
- 按月录入：基本工资、绩效工资、补贴、税前总额、个税、五险一金个人部分、实发工资。
- 列表按月份展示，支持查看单月收入构成。
- 本期不做自动计算，仅记录实际到账数字。

### 2.4 五险一金
- 按月录入：养老、医疗、失业、工伤、生育、公积金（个人+公司分别记录）。
- 与工资月份关联，可查看每月缴纳明细。

### 2.5 请假记录
- 字段：请假类型（年假/病假/事假/调休/其他）、开始日期、结束日期、天数、事由、状态。
- 列表 + 按年统计剩余年假（手动维护年假总额）。

### 2.6 日程安排
- 事件字段：标题、时间范围、地点、备注、是否全天。
- 月/周/日三种视图（先用月视图 + 列表视图）。
- 本期不与外部日历同步。

## 3. 数据模型（核心表）

```text
sys_user          -- 用户（复用现有认证）
mail_message      -- 邮件（发件人、主题、正文、收取时间、是否已读、原始 UID）
work_task         -- 工作事项（标题、内容、计划日期、状态、优先级、mail_id）
salary_record     -- 工资记录（年月、各项金额）
social_insurance  -- 五险一金（年月、险种、个人缴纳、公司缴纳）
leave_record      -- 请假记录（类型、起止、天数、事由、状态）
calendar_event    -- 日程事件（标题、起止、是否全天、地点、备注）
```

## 4. 后端接口规划

| 模块 | 主要接口 |
|------|----------|
| 邮件 | `GET /api/mails`, `GET /api/mails/{id}`, `POST /api/mails/{id}/tasks`, `POST /api/mails/sync`（手动触发拉取） |
| 任务 | `CRUD /api/tasks`, `GET /api/tasks/today` |
| 工资 | `CRUD /api/salary` |
| 五险一金 | `CRUD /api/social-insurance`, `GET /api/social-insurance/month/{ym}` |
| 请假 | `CRUD /api/leaves`, `GET /api/leaves/year/{year}/summary` |
| 日程 | `CRUD /api/calendar-events`, `GET /api/calendar-events/range?start=...&end=...` |

## 6. 实施阶段

### 第一阶段：骨架与数据（约 1 周）
1. 创建 6 张核心表（MyBatis-Plus entity/mapper/service/controller）。
2. 打通前后端基础 API，先做工资/五险一金/请假/日程的手工 CRUD。
3. 前端基础布局 + 侧边导航 + 各模块列表页。

### 第二阶段：邮件与工作流（约 1 周）
1. 配置 IMAP 拉取任务（Jakarta Mail），存储邮件到 `mail_message`。
2. 邮件列表、详情页。
3. “从邮件创建任务”功能。
4. 首页今日工作聚合。

### 第三阶段：收尾与优化（约 2-3 天）
1. 字段校验、分页、空状态。
2. 简单统计（本月工资、本年请假天数）。
3. 自测主路径，修复明显问题。

## 7. 风险与简化建议

| 风险 | 简化方案 |
|------|----------|
| IMAP 授权码/密码安全 | 配置项先使用环境变量或 Spring 加密，不上传到仓库 |
| HTML 邮件 XSS | 展示前使用 HTML 白名单过滤，或默认显示纯文本版本 |
| 邮件附件 | 本期不处理附件下载，只记录是否有附件 |
| 多人使用 | 本期按单人设计，所有数据默认归属当前登录用户 |
| 自动解析邮件 | 本期不做，避免误生成任务 |
